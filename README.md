# JTC SDD Extension (jtc-sdd-ext) v2

Gemini CLI を活用して、ソフトウェア設計プロセス（SDD: Software Design Document）を体系的に管理・支援するための次世代拡張機能です。

## 概要

`jtc-sdd-ext` は、日本の伝統的な企業（**JTC: Japanese Traditional Company**）における重厚な設計知見を、現代の AI 開発プロセスに融合させた設計フレームワークです。

v2 では、**「機械的に保証されるトレーサビリティ」**と**「低コストな設計移行」**をコア・バリューとし、バリデータのモデル・サーバー化とスキルの 6 大グループ統合により、大規模・高速開発における品質と柔軟性を両立させます。

## コア・コンセプト (v2)

### 1. 6 大プロフェッショナル・グループによる統制
複雑化したスキルを 6 つの責任範囲の広い役割に再編。エージェント間のバトンタッチに伴うコンテキスト喪失を最小化し、一貫した設計思想を維持します。

### 2. モデル・サーバーとしてのバリデータ
バリデータは単なるチェッカーから、プロジェクトの全貌を把握する「情報ハブ」へと進化しました。クエリ機能（Impact, Tree, Summary）を通じて、変更の影響範囲を秒単位で特定し、安全な設計変更（移行）をサポートします。

### 3. マネージド・マイグレーション (要求の上書き管理)
既存の要求を塗り替える新しい要求が発生した際、破壊的な変更ではなく「管理された進化」として扱います。新旧 ID の対応付けと、コード内の ID タグの外科的な貼り換えを、バリデータの支援のもとで確実に実行します。

## ID ツリー構造 ＆ トレーサビリティ

本拡張機能は、以下の ID 体系に基づき、設計の網羅性と一貫性を管理します。

| レベル | ID | 管理ドキュメント | 役割・説明 |
| :--- | :--- | :--- | :--- |
| **L1: 要求** | `REQ-XXX` | `requirements.md` | **ユーザーの意図**: 「何を実現したいか」という最上位のビジネス要求。 |
| **L2: 要件** | `SPEC-XXX` | `REQ-XXX.md` | **具体的要件**: 要求を分解した詳細仕様。 |
| **L3: データ** | `DATA-XXX` | `REQ-XXX.md` | **論理データ**: システムが扱うデータの構造と不変条件。 |
| **L4: 機能** | `FUNC-XXX` | `REQ-XXX.md` | **論理機能**: 要件を実現するための具体的なロジック定義。 |
| **L5: 物理** | `COMP-XXX` | `architecture.md` | **コンポーネント**: 物理的なモジュール/ファイルへの割り当て。 |
| **L6: ユニット** | `UNIT-XXX` | `architecture.md` | **最小単位**: クラスや関数レベルの物理的な実装単位。 |
| **L7: 試験** | `TEST/ACC` | `tests/` | **検証項目**: 結合試験 (TEST) および総合試験 (ACC)。 |

### トレーサビリティの例
- `REQ-001` (ログインしたい)
    - `ACC-001` (ログインからマイページ表示までのユーザー導線)
    - `SPEC-001` (ID/PASSによる認証を行う)
        - `DATA-001` (ユーザー資格情報：ID, パスワード, 有効期限)
        - `FUNC-001` (ユーザー認証・トークン発行処理)
            - `COMP-001` (認証サービス / AuthModule)
                - `UNIT-001` (`src/auth/AuthService.ts::verifyCredentials`)
            - `TEST-001` (認証ロジックの正常・異常系判定)

## 6 大プロフェッショナル・グループ

1. **Workflow & Strategy**: 全体の進行管理、実行モード（通常・プロトタイプ・移行）の決定。
2. **Requirements & UX**: 要求抽出、画面遷移（Uiflow）設計、要求マップの管理。
3. **System Design**: 論理設計（SPEC/FUNC/DATA）と物理構造（architecture.md）の同期。
4. **Software Engineering**: TDD 実装、コード内の ID コメント埋め込み、スキル作成。
5. **Test Engineering**: 結合試験（TEST）および総合試験（ACC）のシナリオ作成。
6. **Quality Assurance**: 整合性チェック、網羅性の証明、不整合の検出。

## 主な特徴 (v2 新機能)

- **クエリ・インターフェース**: `impact <ID>` (影響範囲特定), `tree <ID>` (垂直構造可視化), `summary` (進捗サマリー)。
- **セクション単位スニペット**: `<!-- [SECTION:XXX] -->` マーカーを用いた、追記・置換が容易なドキュメント管理。
- **ID コメントの標準化**: `// @logic [FUNC-ID]`, `// @data [DATA-ID]` 等の「種別明記」による高精度な解析。
- **自動昇華プロセス**: プロトタイプ (`REQ-PROTO.md`) から堅牢設計への自律的な展開。

## 使い方

### バリデータの実行 (モデル・サーバー機能)

```bash
# 進捗サマリーの表示
node jtc-sdd-ext/dist/validator/main.js projects/[名] --query summary

# 特定 ID の変更による影響範囲（ファイル・ID）を特定
node jtc-sdd-ext/dist/validator/main.js projects/[名] --query impact --id REQ-001

# テストが不足している SPEC/REQ の一覧を表示
node jtc-sdd-ext/dist/validator/main.js projects/[名] --query list-missing-tests
```

詳細な運用ルールやスキルの使い方は `jtc-sdd-ext/GEMINI.md` を参照してください。
